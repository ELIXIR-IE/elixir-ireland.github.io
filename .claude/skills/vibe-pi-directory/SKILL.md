# VIBE PI Directory

All PI cards live in one file: `_includes/vibe_pis.html`. It's a flat list
of `.pi-card` divs, included into `vibe/index.html`. There is no separate
data file/JSON — it's hand-written HTML, so precision in the markup matters
more than usual.

## 1. Card template

Copy this structure exactly (indentation isn't load-bearing but keep the
element structure and classes):

```html

    <h3>Dr./Prof. Full Name</h3>
    <h4>Job title / position</h4>
    <p class="affiliation">EXACT Institution Name</p>
    <div class="pi-links">

        <a href="https://example.org/profile" target="_blank" class="pi-link" title="Profile">
            <svg xmlns="http://www.w3.org/2000/svg" width="20" height="20" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
```

- No photo available? Use the placeholder icon instead of `<img>` (copy
  from any existing placeholder card — a person silhouette SVG with class
  `placeholder-icon`).
- No profile/website link, or no ORCID? Just omit that `<a>` — an empty
  `pi-links` div is fine (several existing cards have zero links).
- An `mailto:` email link (envelope icon) is also used on a few cards —
  copy from Aedín Culhane's card if one is supplied.

## 2. `data-affiliation` MUST exactly match the institution's existing string

This is the one thing that silently breaks if you get it wrong. The
institution filter chips and counts on `/vibe/` are generated by grouping
`.pi-card` elements by their literal `data-affiliation` string
(`assets/js/vibe.js`, `buildPiFilterBar()`). A typo or variant spelling
(e.g. `"Queen's University Belfast"` vs the actual `"Queens University
Belfast"` used throughout this file — no apostrophe) creates a **second,
fragmented chip** instead of joining the existing group.

Before adding a card, grep the file for the institution to reuse its exact
string:
```bash
grep -o 'data-affiliation="[^"]*"' _includes/vibe_pis.html | sort -u
```
Canonical strings currently in use: `Dublin City University`, `Maynooth
University`, `Munster Technological University`, `Queens University
Belfast`, `RCSI`, `Teagasc`, `Technological University Dublin`, `Trinity
College Dublin`, `Ulster University`, `University College Cork`,
`University College Dublin`, `University of Galway`, `University of
Limerick`.

New institution not in that list? Add it (any spelling is fine as a
*new* group), and also add a short-name entry to `INSTITUTION_SHORT` in
`assets/js/vibe.js` so its filter chip shows a clean abbreviation instead
of the full name.

## 3. Filter chip order is automatic — don't hand-order anything

`buildPiFilterBar()` in `assets/js/vibe.js` sorts institution chips
alphabetically by their short display name (`localeCompare` on the
`INSTITUTION_SHORT` value), every time the page loads. It always produces
e.g. `DCU, Galway, Maynooth, MTU, QUB, RCSI, TCD, Teagasc, TU Dublin, UCC,
UCD, UL, Ulster` regardless of what order the cards appear in the HTML
file. **You never need to reorder cards in the file for the chips to be
alphabetical** — just append new cards wherever convenient (end of file is
simplest) and get `data-affiliation` right; the UI sorts itself.

Cards are hidden by default and only shown once a filter chip is clicked
(`toggleFilter`) — so a plain screenshot of `/vibe/` right after load will
show the filter bar with correct counts, but not the actual card grid.
That's expected, not a bug.

## 4. Sourcing a new PI's details (do this — don't guess)

Get a URL from the user (institutional profile page, Pure/Research
Portal, lab page) and actually fetch it — don't infer rank/title from the
name or institution alone:

- **Job title/rank**: Institutional "profile" or "find-a-phd-supervisor"
  pages often *omit* the academic rank entirely (just "Dr So-and-so").
  The institution's research-information-system profile (Pure, Elements,
  etc. — often linked from the page as "Pure profile" / "Research
  Portal") is usually more reliable and states the rank explicitly next
  to the name (e.g. "Reader", "Professor", "Senior Lecturer"). If you
  can't confirm the rank from a source page, don't assert one — use a
  neutral descriptor instead (e.g. "Group Leader, X" or just their
  research area) and flag to the user that it's unconfirmed.
- **ORCID**: usually linked directly on the page, or embedded in a
  schema.org `Person` JSON-LD block (`"sameAs": ["https://orcid.org/..."]`
  or a bare `orcid.org/...` string in the page).
- **Photo**: Pure-style portals typically serve a profile photo at a
  `/files-asset/...` path with an `<img alt="Full Name">` tag — grab that
  URL directly. Save to `assets/images/firstname-lastname.jpg` (lowercase,
  hyphenated, matches existing file naming).
- Some institutional sites block plain `curl` (Cloudflare/WAF — you'll
  get a 403 or a generic "request could not be satisfied" error). Retry
  with a full browser `User-Agent` and `Accept`/`Accept-Language`
  headers; that alone resolves most of these.

## 5. Verify

```bash
docker compose up -d --build   # if not already running (see README)
grep -c 'data-affiliation="Institution Name"' _includes/vibe_pis.html
curl -s http://localhost:4000/vibe/ | grep -c "New PI Name"
```
The count should match what the rendered filter chip shows for that
institution (fetch `/vibe/`, or screenshot it — the chip bar renders
without needing to click anything, per §3).
